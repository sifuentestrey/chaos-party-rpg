# Free AI Dungeon Master research and decision

Research date: 2026-10-26 (America/Chicago). The owner requires strictly free AI, with no paid fallback. This document distinguishes provider claims from tests in this project.

## Decision

First real candidate: Groq Free Plan, `openai/gpt-oss-20b`, low reasoning effort, hosted inference. The model is open-weight under Apache 2.0 according to its publisher; the hosted service is a third party. One server-side connection serves the group, while the existing Mac runs the game, TV display and authoritative rules. This is a candidate, not a qualified model. Validate the provider's current model availability and actual Free Plan organization limits before use.

The integration and fixed interpretation/narration benchmarks are prepared in this branch. Tests use synthetic responses; no Groq account, key or live inference was configured or run here. An optional post-outcome narrator and bounded canonical/NPC memory are now implemented; see [the implementation checkpoint](AI_DM_PROGRESS.md). The full creative DM experience and generated event proposals are incomplete. **Do not claim the problem solved until real interpretation and narrative tests pass.**

Open weight does not mean compute is unlimited or free. Free hosted inference has quotas, availability and data terms; local inference requires hardware and electricity. The Mac's actual performance has not been measured. Training a foundation model from scratch is not justified here. Fine-tuning an existing model could later improve specific interpretation/narration patterns, but it needs a rights-cleared dataset, testing and sufficient compute; it does not by itself fix slow inference. A persistent world database, retrieved memories, careful prompts and deterministic game rules are the first priority.

## How long might free last?

The published Groq 1,000 requests/day is **not** the same as 1,000 full AI turns. Token/minute and token/day ceilings may hit first, and the organization limits can differ. The current game adapter additionally limits itself to **100 inference attempts/day and four/minute** per game data directory; this is our conservative setting, not Groq's. It can be adjusted after real measurement, within provider terms.

Illustrations only, not measured quotas or promises: with one model request per turn, 100 requests permit at most 100 turns/day; with separate interpretation and narration requests, at most 50 turns/day. At one turn/minute those would be at most 100 or 50 minutes respectively; at one turn/15 seconds, 25 or 12.5 minutes. Native actions that skip AI can stretch the allowance. Actual duration may be shorter if a request uses enough tokens to hit Groq's token limits, retries are initiated manually, requests fail, or account limits are lower. Player reactions do not need one call per phone. Do not work around provider limits by creating extra accounts.

Use compact context: current location, relevant entity IDs/conditions, the immutable declaration, the applicable rules and bounded relevant history. Measure actual prompt and output tokens instead of guessing. A future option is to request bounded success/failure narration candidates alongside interpretation and let the server choose after its roll, but this is an unimplemented design experiment: it could omit later reactions or contradict outcomes and must pass narrative quality tests. A second, asynchronous post-outcome narration request may produce better grounded stories but uses quota. The rules, visual feedback and reactions must remain responsive in either approach.

## Game-specific qualification

1. Explicitly confirm a Free Plan organization with no billing/payment method. Create a key in the provider UI; never paste it into chat. Set `GROQ_API_KEY` via an appropriate secret vault, `CHAOS_AI_PROVIDER=groq-free` as a non-secret variable, and permit `api.groq.com` in the task environment. The existing task's enforced policy does not include this host; publishing a new environment may require a fresh task. Preserve current source checkpoint first: `feature/creative-dm` at the latest local commit and its parent campaign `c0c1ff0`. These commits are not known to be pushed to GitHub.
2. Run `node scripts/benchmark-campaign-ai.mjs`. It exercises twelve fixed meanings and checks targets, existing components, ownership and appearance—not just JSON validity. Report every response, failure, provider model, prompt/output token usage, p50/p95 and correct-within-5.5-seconds. The harness spaces hosted calls, uses test-only game state, rejects unknown proposals and has no paid fallback. Treat 12 cases as a gate, not a statistical guarantee. Confirm actual in-game reaction concurrency and late-result rejection too.
3. Separately test the core DM appeal: a bartender deception/threat scene, funny in-character dialogue after the roll, reactions from several players, unexpected but supported item outcomes, NPC names/relationships and remembered consequences in a later location and after reload. Judge whether the narration is entertaining and truthful. A model must not award items, damage, coins or scene changes through prose; unsupported outcomes cannot be presented as applied. The optional layer is implemented with synthetic protocol/lifecycle tests, but has no real-model semantic qualification.
4. Measure token use and responsiveness for a realistic 12–20-person party on the actual Mac/TV and two real phones, including a 90-second playthrough and multi-hour quota projection. Do not claim target hardware speed from the Linux worker. If quota or quality fails, test another free model/provider or suitable existing private hardware; stay free and maintain a clear no-AI rules fallback.

Privacy: scene and declaration text go to the chosen provider; player device tokens, PINs, host keys and RNG seed are excluded. [Groq data handling](https://console.groq.com/docs/your-data) describes retention for reliability/abuse and a configurable zero-data-retention option; actual account eligibility and settings must be checked. Inform participants when hosted AI is enabled.
